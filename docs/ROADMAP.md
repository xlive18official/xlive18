# XLive 18 — خطة التنفيذ والحالة الحالية

## قواعد المشروع

- واجهة عربية كاملة واتجاه RTL، مع أولوية للهاتف وهوية سوداء وحمراء.
- لا تُعرض بيانات تجريبية على أنها بيانات حقيقية.
- لا تُعتبر أي ميزة مكتملة قبل ربطها بالخادم وقاعدة البيانات والخدمات واختبارها.
- لا يُنشر الفيديو للعامة قبل موافقة المراجعة.
- تُفرض صلاحيات الوصول على الخادم، لا بمجرد إخفاء عناصر الواجهة.
- لا تُفعّل المدفوعات أو البث أو الغرف الصوتية/المرئية قبل اختيار الخدمات واختبارها.
- تُجرى تغييرات صغيرة يمكن مراجعتها، مع الحفاظ على الملفات الموجودة.

## الحالة المؤكدة

### موجود في المستودع
- فُحص الفرع `main` وصلاحية الكتابة، وتأكد Commit اختبار الاتصال.
- `index.html` و`styles.css` و`app.js`: واجهة أولية عربية متجاوبة وتنقل محلي.
- `auth.js` و`supabase-config.js`: واجهة تسجيل/دخول/استعادة كلمة المرور متصلة بعميل Supabase باستخدام المفتاح العام فقط؛ أضيفت اختبارات ثابتة للتوصيل.
- ملفا الترحيل `0003_restrict_internal_function_execute.sql` و`0004_index_foreign_keys.sql` يوثّقان تصحيح صلاحيات الدوال والفهارس.
- `supabase/migrations/0001_initial_schema.sql`: مسودة جداول الحسابات والملفات الشخصية والمتابعة والحظر والفيديوهات والغرف والبلاغات والإشعارات والمشتريات، مع سياسات RLS.
- `supabase/migrations/0002_private_video_storage.sql`: bucket خاص للفيديوهات وسياسات تحميل محدودة بمجلد المستخدم.
- `supabase/migrations/0005_restrict_private_profile_reads.sql`: تقييد قراءة الحسابات الخاصة بصاحب الحساب فقط.
- `supabase/migrations/0006_remove_follows_on_block.sql`: حذف المتابعات المتبادلة تلقائياً عند الحظر.
- `supabase/migrations/0007_restrict_follows_to_public_profiles.sql`: منع المتابعة المباشرة للحسابات الخاصة.
- `supabase/migrations/0008_private_profile_follow_requests.sql`: جدول طلبات متابعة للحسابات الخاصة، مع قبول/رفض من صاحب الحساب وحذف الطلبات عند الحظر.
- `supabase/migrations/0009_profile_discovery_and_follow_request_hardening.sql` و`0010_allow_unblock_from_account_search.sql` و`0012_limit_profile_search_to_authenticated_users.sql` و`0013_tighten_profile_search_and_follow_request_transitions.sql` و`0014_optimize_rls_policy_evaluation.sql` و`0015_direct_messages_and_social_notifications.sql` و`0016_approved_video_delivery_and_review_notifications.sql` و`0017_room_cancellation_and_video_review_validation.sql` و`0018_require_longer_authenticated_profile_search.sql`: بحث للحسابات المسجلة فقط، بادئة من ثلاثة أحرف و20 نتيجة كحد أقصى، وإغلاق انتقالات طلب المتابعة بعد القبول أو الرفض.
- `supabase/README.md`: خطوات تشغيل الترحيلات يدوياً.
- `docs/PROVIDER_DECISIONS.md`: مقارنة مبدئية للمزوّدين والحصص المجانية ومخاطر سياسة المحتوى.

### لم يُنفّذ أو يُختبر بعد
- مشروع Supabase `xlive18` موجود ونشط؛ الجداول التسعة موجودة وRLS مفعّل عليها.
- تم تطبيق تصحيح صلاحيات الدوال الداخلية. فحص Supabase الحالي ما زال يعرض تحذيراً واحداً عن دالة البحث `SECURITY DEFINER`، وهو مقيد بالمستخدمين المسجلين والحقول المحدودة وبادئة بحث ونتائج محدودة لكنه يحتاج مراجعة قبل الإنتاج. فحص الأداء لم يعد يعرض تحذيرات سياسات RLS؛ بقيت معلومات فهارس غير مستخدمة، وهو متوقع قبل وجود بيانات وحركة استخدام.
- تم التحقق من وجود الفهارس الثمانية المضافة في قاعدة البيانات.
- طُبقت ترحيلات 0005–0014 ذات الصلة على Supabase؛ ترحيل 0008 يضيف طلبات المتابعة للحسابات الخاصة. أضيفت اختبارات ثابتة لهذه القيود، لكن لم يُثبت تشغيل مجموعة الاختبارات أو اختبار قبول/رفض فعلي بحسابين بعد.
- واجهة المصادقة موصولة بعميل Supabase، وأضيفت واجهة بحث الحسابات وأزرار المتابعة/طلب المتابعة/القبول/الرفض/الحظر/إلغاء الحظر. لم يُختبر إنشاء حساب حقيقي أو هذه التدفقات من متصفح بعد؛ لذلك لا تُعد المصادقة والتفاعلات مجتازة للاختبار حتى الآن. أضيف مسار GitHub Actions لتشغيل فحص JavaScript والاختبارات عند الدفع أو فتح طلب دمج. تم فحص التحليل النحوي لملفات JavaScript، لكن نتيجة تشغيل CI الفعلية غير مؤكدة. دالة البحث SECURITY DEFINER محدودة للمستخدمين المسجلين وتعيد بيانات تعريفية فقط؛ ما زال مستشار Supabase يعرض تحذيراً لهذه الدالة ويحتاج مراجعة أمنية قبل الإنتاج.
- أضيف رفع فيديو إلى bucket خاص مع حد 50 ميغابايت وصيغ محددة، وإدخال metadata بحالة `pending`، ومشاهدة المقاطع المقبولة المجانية العامة، وأزرار مراجعة للمستخدم الذي يحمل دور admin. لا يوجد فحص آلي للمحتوى أو تحويل/ضغط فيديو أو معاينة مدفوعة؛ ولا يزال اختبار رفع ومراجعة فعلي مطلوباً.
- أضيف جدول الرسائل الخاصة بسياسات RLS، وواجهة المحادثات وإرسال الرسائل وإيصالات القراءة، مع إشعارات آلية للرسائل والمتابعة وطلبات المتابعة. لا يزال اختبارها بحسابين حقيقيين مطلوباً.
- أضيف إنشاء طلبات غرف صوتية/مرئية وحفظها بحالة pending مع إمكانية إلغائها؛ لم يتم ربط WebRTC/SFU أو إصدار رموز الدخول، لذلك لا يمكن بدء بث حقيقي.
- لا توجد بوابة دفع أو مشتريات حقيقية.
- لا يوجد نشر إنتاجي أو اختبار متصفح آلي موثق.

## مراحل التنفيذ

1. **تأسيس الواجهة:** RTL، التصميم المتجاوب، التنقل وحالات الخطأ.
2. **اعتماد الخدمات:** إنشاء حسابات المزوّد بواسطة مالك المشروع، ومراجعة سياسة المحتوى +18 والتكلفة قبل اعتماد التخزين والبث والدفع.
3. **قاعدة البيانات والمصادقة:** اختبار الترحيلات، إعداد المصادقة، توصيل الواجهة، واختبارات RLS بحسابين مختلفين.
4. **الفيديو والمراجعة:** رفع آمن، حالات المراجعة، صلاحيات الإدارة، نشر المقبول فقط، والإبلاغ.
5. **المحتوى المدفوع:** اختيار مزوّد دفع يقبل النشاط كتابةً؛ معاينة مجانية لخمس ثوانٍ؛ تسليم الفيديو الكامل عبر مسار محمي بعد تحقق الخادم من الدفع.
6. **الغرف والبث:** اختيار خدمة اتصال مناسبة ومتوافقة؛ إصدار رموز الغرف من الخادم فقط؛ اختبار الصوت والفيديو والأذونات والمغادرة والبلاغات.
7. **الرسائل والإشعارات والبحث:** تخزين محمي، صلاحيات لكل محادثة، وإظهار المحتوى المسموح فقط.
8. **لوحة الإدارة والأمان:** مراجعة المحتوى والبلاغات وسجل الإجراءات واختبارات الوصول غير المصرح به.
9. **الاختبار والإطلاق:** اختبارات الهاتف والكمبيوتر، الروابط والأزرار، الرفع والتشغيل والصلاحيات والدفع، ثم توثيق النشر.

## خيارات الاستضافة المجانية

راجع [مقارنة المزوّدين](PROVIDER_DECISIONS.md). الحصص المجانية تصلح للتجربة وليست ضماناً لاستمرار منصة فيديو وبث بلا تكلفة. يجب التأكد من سياسة كل مزوّد تجاه المحتوى المقصود قبل تحميل محتوى حقيقي.

## قرار الأمان

لا توضع مفاتيح خدمة Supabase أو مفاتيح LiveKit السرية أو أسرار الدفع في المتصفح أو المستودع. يجب أن تتم مراجعة المحتوى، وتغيير حالة الغرف، والتحقق من الدفع، وإصدار روابط الفيديو الموقعة من خادم موثوق.
